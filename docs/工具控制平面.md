# 本地 AI 工具控制平面 + MCP 编排

黑鲸启动器不仅是 DSH 的进程管家,还是本地 AI 工具的「DSH 友好控制平面」:
管理每个工具的进程 / 端口 / 健康 / 日志,并把工具的 MCP server 自动注册进 DSH。

## 插件式工具注册(tools.yml)

配置文件在启动器数据目录 `tools.yml`(首次打开「工具」页自动生成模板)。
每个工具一个条目,修改后点面板「重新加载配置」立即生效。

```yaml
dshProfile: web            # MCP 注入目标 DSH profile(默认 web)
tools:
  - id: comfyui            # 唯一 id
    name: ComfyUI
    command: python        # 可执行文件
    args: ['main.py', '--port', '@PORT@', '--listen', '127.0.0.1']
    cwd: ~/ComfyUI         # 工作目录,支持 ~;空 = 启动器数据目录
    port: 8188             # 期望端口;0 = 自动分配;被占自动后移
    health: 'http://127.0.0.1:@PORT@/system_stats'   # GET 200-399 健康
    # 或 MCP 探测:health: 'mcp:http://127.0.0.1:@PORT@/mcp'
    readyPattern: 'To see the GUI'   # 可选:日志就绪标志(替代/补充 health)
    env: {}                 # 追加环境变量
    mcp:                    # 可选:就绪后自动注册进 DSH
      serverName: comfyui
      transport: streamable-http
      url: 'http://127.0.0.1:@PORT@/mcp'

  - id: comfyui-mcp        # artokun/comfyui-mcp(108 tools)
    command: npx
    args: ['-y', 'comfyui-mcp@latest', '--http', '--port', '@PORT@', '--comfyui-url', 'http://127.0.0.1:8188']
    port: 9100
    health: 'mcp:http://127.0.0.1:@PORT@/mcp'
    mcp:
      serverName: comfyui-mcp
      transport: streamable-http
      url: 'http://127.0.0.1:@PORT@/mcp'

  - id: ollama
    name: Ollama
    command: ollama
    args: ['serve']
    port: 11434
    health: 'http://127.0.0.1:@PORT@/api/tags'

  - id: whisper-stdio      # stdio 型:无需本启动器管理进程,DSH 自己拉起
    name: faster-whisper (stdio)
    manage: false
    mcp:
      serverName: whisper
      transport: stdio
      command: uvx
      args: ['faster-whisper-mcp']
```

- `@PORT@` 在启动时被替换为实际分配端口
- `manage: false` = 虚拟工具:不管进程,只负责把 MCP 注册进 DSH(stdio 直连场景)

## 核心机制

### 进程生命周期(跨平台)
- 启动:spawn detached + PID 文件(数据目录 tools/pids/),日志落盘(tools/logs/<id>.log)
- 停止:进程树终止(mac/Linux: SIGTERM→SIGKILL;Windows: taskkill /T /F)
- 重启 / 全部启动 / 全部停止
- 启动器崩溃重启后按 PID 文件自动接管仍在运行的工具

### 端口管理
- 期望端口被占或为 0 → 从该端口起自动后移寻找空闲端口(本机探测)
- 已分配端口记录进 state,防止工具之间冲突

### 健康检查(5s 巡检)
- 进程存活 + HTTP 探测(或 MCP initialize 探测)
- 启动观察:90 秒内等待健康或 readyPattern,失败带日志尾部报错
- 进程异常退出 → 状态置「异常」+ 日志尾部摘要

### MCP 编排(核心创新点)
1. 工具运行且健康(或 manage:false)后,自动探测 MCP tool list:
   - streamable-http:JSON-RPC initialize + tools/list(支持 session id)
   - stdio:spawn 后逐行 JSON-RPC 握手,读完即释放
2. 工具清单数量展示在面板(MCP · 108 工具)
3. 按 dsh-mcp-client 官方格式写入 `<DSH_HOME>/profiles/<profile>/cordis.patch.yml` 的自动生成区块:
```yaml
# >>> dsh-launcher-mcp-auto(由黑鲸启动器自动生成,请勿手改)
- id: mcp-comfyui-mcp
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: comfyui-mcp
    transport: streamable-http
    url: 'http://127.0.0.1:9100/mcp'
# <<< dsh-launcher-mcp-auto
```
4. 工具停止 / 不健康 → 该条目自动撤下;区块外的用户手写内容永不触碰
5. DSH 侧:dsh-mcp-client 支持 HMR 热加载(编辑即断线重连),无需重启;
   面板也提供「重启 DSH 生效」按钮(仅限本启动器启动的 DSH,防止误杀他人实例)

## 不做的事(边界)

- 不统一 Python 虚拟环境(用户工具用什么环境就配什么 command)
- 不管理模型权重/下载
- 不做 GPU 调度
- 不做账号系统(纯本机单机)

## 面板

侧栏「工具」页:全部启停、逐工具 启动/停止/重启/日志(2s 自动刷新弹窗)、
端口与健康状态、MCP 工具数与注入状态、DSH 运行状态与「同步 MCP / 重启 DSH」。
